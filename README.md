# HTML Reader

아이폰에서도 PDF 리더로 PDF를 열듯이, 저장된 HTML 파일을 열고 **그 파일에 포함된 CSS와 JavaScript 기능까지 사용하는 HTML 리더**입니다. 모의고사는 여러 검증 파일 중 하나이며, 앱이 정답이나 채점 기능을 새로 만드는 제품이 아닙니다.

현재 구현은 Safari와 PC 브라우저에서 사용하는 웹 리더입니다. 기기에서 HTML을 선택해 읽고 실행하며 소스를 수정할 수 있습니다. 최종 설치형 iOS 리더의 파일 앱 연결은 별도 구현이 필요합니다. Mattermost 연동은 제품의 핵심 요구사항이 아닙니다.

- [요구사항 명세서](docs/requirements.md)
- [아이폰 검증과 설치형 앱 단계](docs/ios-validation.md)

## 사용 흐름

**HTML 열기 → 파일 선택 → 읽기 및 기능 사용 → 보관 목록에서 다시 열기**

소스 편집은 보조 기능입니다. 편집한 내용은 초안으로 저장하며, **적용하고 실행**을 눌렀을 때만 현재 문서를 다시 실행합니다.

## 현재 기능

- UTF-8 `.html` / `.htm` 파일 가져오기. 여러 파일 선택과 PC에서 끌어다 놓기. 파일당 최대 5MiB.
- 파일 목록, 이름과 문서 제목 검색, 최근 열람순/이름순/가져온 순 정렬.
- 파일 내부 HTML, CSS, JavaScript 실행. 버튼, 입력, 계산, DOM 변경, alert와 confirm.
- 아이폰 화면을 넓게 사용하는 **넓게 읽기**와 종료 버튼. Safari의 전체 화면 API에 의존하지 않습니다.
- 원본 소스, 편집 초안, 마지막 실행본과 파일별 저장 데이터를 기기의 IndexedDB에 보관.
- 파일별 localStorage 격리와 재열람 복원. 원본 문서가 저장하지 않는 입력값과 DOM 상태는 자동 복원하지 않습니다.
- 소스 편집, 구문 강조, 입력 보조, 초안 저장, 실행 취소/다시 실행, 원본 복구와 명시적 재실행.
- 원본 소스와 수정본을 구분한 UTF-8 HTML 내보내기. localStorage 값은 HTML 소스에 자동 포함하지 않습니다.
- 별도 CSS, JS, 이미지 등 리소스 연결 안내. 별도 파일을 함께 가져오는 기능은 아직 지원하지 않습니다.
- 실제 HTML 계산기와 저장 메모 예제. 기존 모의고사는 접힌 **예제 파일로 확인** 메뉴에서 사용할 수 있습니다.
- 프로덕션 빌드의 앱 및 예제 캐시를 이용한 오프라인 실행.

## 설치와 실행

Node.js 22.12 이상 또는 24 LTS를 사용합니다. `package.json`이 있는 폴더에서 실행하세요.

```sh
npm ci
npm run dev
```

PC에서는 표시된 Local 주소로 접속합니다. 같은 네트워크의 휴대폰에서는 Network 주소를 사용합니다. PC 유선망과 아이폰 LTE는 같은 네트워크가 아니므로, 이 경우 아래 HTTPS 배포를 사용합니다.

```sh
npm run build
npm run preview
```

배포 파일은 `dist/`에 생성됩니다. `dist/index.html`을 파일 앱의 미리보기나 탐색기에서 직접 열지 않고 HTTP 서버 또는 HTTPS 정적 호스팅으로 실행합니다.

## 아이폰 Safari에서 확인

1. 기존 Netlify 프로젝트의 배포 영역에 새로 빌드한 `dist` 폴더를 업로드합니다. 기존 프로젝트 주소를 유지하면 같은 출처의 기존 파일 데이터를 계속 사용할 수 있습니다. 새 사이트 주소를 만들면 저장 데이터가 자동 이전되지 않습니다.
2. Safari에서 HTTPS 주소를 엽니다. **HTML 열기**를 눌러 파일 앱에 저장한 HTML을 선택합니다.
3. 계산기, 입력 폼, 문서 읽기 등 실제 파일의 기능을 사용합니다. 서버 기능은 앱이 대신 제공하지 않습니다.
4. 파일을 여러 개 열어 보관 목록과 검색을 확인하고, **넓게 읽기**에서 종료 버튼으로 돌아옵니다.
5. 저장 기능이 있는 문서에서 데이터를 저장합니다. 리더의 **저장됨**을 확인하고 페이지를 다시 엽니다.
6. 소스를 변경하고 적용합니다. 원본 내보내기와 수정본 내보내기의 내용이 구분되는지 확인합니다.
7. 프로덕션 화면 하단의 **오프라인 준비 완료**를 확인하고 페이지를 다시 연 뒤, 비행기 모드에서 재열람을 확인합니다. 개발 서버에서는 서비스워커를 사용하지 않습니다.

사이트가 비밀번호나 로그인으로 보호되어 있다면 해당 접근 절차를 먼저 완료해야 합니다. 홈 화면 추가, 오프라인 실행 및 저장 복원은 각각 검증합니다. Safari에서 정상이라고 설치형 WKWebView 앱까지 검증된 것은 아닙니다.

## 테스트

```sh
npx playwright install chromium
npm test
npm run test:production
```

이미 설치된 Chromium이 있다면 `CHROMIUM_PATH`로 실행 파일을 지정할 수 있습니다. 시스템 라이브러리가 필요하면 Playwright의 설치 안내를 따릅니다.

- `tests/reader.spec.js`: 일반 HTML 다중 가져오기, 제목 검색/정렬, 계산기 및 저장 메모, 파일별 저장 복원, 원본 내보내기, 모바일 넓게 읽기, 리소스 안내, 이전 버전 저장 데이터 호환성.
- `tests/core.spec.js`: 기존 모의고사 실행, 원본 채점/해설, 답안과 타이머 복원, 파일 격리.
- `tests/workflow.spec.js`: 편집/저장/내보내기, 중복 파일, 저장 실패 및 복구, 실행 영역 격리, 모바일 배치.
- `tests/production.spec.js`: 프로덕션 오프라인 재열람과 실제 화면 검사.

2026-10-12 기준 Node.js 24 / Chromium 153에서 개발 검사 18개와 프로덕션 검사 3개, 총 21개가 통과했습니다. 프로덕션 검사에는 실제 빌드와 오프라인 실행이 포함됩니다. 자동 검사는 새 버전의 Safari 실기기 확인을 대신하지 않습니다. 이전 웹 시연판은 사용자가 Safari에서 정상 동작을 확인했습니다.

## 저장과 호환성

기존 IndexedDB 이름 `html-study-v1`과 문서 ID를 유지합니다. 이 변경을 같은 배포 주소에 적용하면 기존 원본, 초안과 문서 저장 데이터를 계속 읽습니다. 브라우저 데이터 삭제나 기기의 저장 공간 회수에서는 보존을 보장하지 않습니다.

HTML은 앱 DOM에 접근할 수 없는 iframe에서 실행하며, 전용 MessagePort를 통해 자신의 저장 데이터만 보냅니다. 기본 localStorage 메서드와 속성 접근을 지원하지만 실제 브라우저 Storage 객체의 모든 기능이나 storage 이벤트를 재현하지는 않습니다. 비동기 저장 실패는 리더와 문서 내부에 표시합니다.

현재 지원 범위는 파일 내부에 필요한 코드와 리소스가 포함된 단일 HTML입니다. 리소스 검사는 일반적인 src, stylesheet, CSS url/import 연결을 안내하는 보조 기능이며 모든 동적 연결을 분석하지 않습니다. 외부 파일, CDN, 서버 API, 모듈 import, iframe 내부 콘텐츠가 필요한 문서는 완전한 동작을 보장하지 않습니다.

외부 리소스는 CSP로 제한하지만 웹 실행 영역의 자체 페이지 이동과 무한 반복을 완전히 차단하지 못합니다. 실행 스레드가 멈추면 실행 종료 버튼도 반응하지 않을 수 있어 탭을 닫고 다시 열어 저장 완료된 내용을 복구해야 합니다. 불특정 HTML을 안전하게 실행하는 완전한 샌드박스로 출시한 상태는 아닙니다.

## 다음 개발 단계

1. 현재 일반 HTML 리더를 Safari 실기기에서 확인하고 파일별 호환성 문제를 수정합니다.
2. HTML과 상대 경로 CSS/JS/이미지를 묶어 가져오는 ZIP 또는 파일 묶음 지원을 추가합니다.
3. 설치형 iOS 앱에서 파일 선택, 보관과 WKWebView 실행 및 저장 복원을 구현합니다. Mac/Xcode와 실기기 검증이 필요합니다.
4. 파일 앱의 파일 열기 연결을 추가합니다. 특정 메신저 연동은 부가 가져오기 경로로 취급합니다.
