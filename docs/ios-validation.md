# 아이폰 검증과 설치형 앱 단계

최종 목표는 아이폰에 저장된 HTML 파일을 PDF 리더처럼 가져와 화면과 기능을 함께 사용하는 것이다. 현재 웹 리더의 완료와 설치형 iOS 앱의 완료를 구분한다.

## 현재 웹 리더 확인

같은 배포 주소에 새 빌드를 적용하고 Safari에서 문서, 계산기, 저장 메모, 기존 모의고사를 각각 확인한다. 파일마다 필요한 자원이 내부에 포함되어 있는지 확인한다. 별도 CSS/JS/이미지가 필요한 문서는 현재 버전에서 의존 안내가 표시되며 전체 동작을 보장하지 않는다.

홈 화면 추가는 Safari 공유 메뉴의 홈 화면에 추가를 사용한다. 홈 화면 실행과 일반 Safari 실행의 저장 및 키보드 동작을 각각 확인한다. 홈 화면에 추가한 것만으로 오프라인 기능이나 설치 앱의 파일 연결이 완성된 것은 아니다.

- HTML/HTM 선택과 다중 선택 후 보관 목록 확인
- 실제 터치, 한글 조합 입력과 읽기 영역 스크롤
- 넓게 읽기에서 종료 버튼으로 돌아오기
- localStorage를 사용하는 파일의 저장 완료 이후 재열람
- 소스 초안과 원본 내보내기 구분
- 캐시 준비 후 비행기 모드에서 앱 재시작 및 이미 가져온 파일 실행
- 기존 주소에 업데이트한 뒤 기존 파일과 저장값 유지

## 설치형 iOS 앱의 다음 구현 범위

파일 선택기로 사용자가 고른 HTML을 앱 내부에 복사하고 보관한다. WKWebView에서 해당 문서를 실행하되, 파일별 저장값을 격리하고 다시 열 때 복원한다. 우선 하나의 완결 HTML을 대상으로 파일 읽기, 클릭과 입력, 문서 저장값 복원을 실기기에서 검증한다.

그 다음 파일 앱에서 앱으로 HTML을 여는 연결을 추가한다. 특정 메신저의 공유 메뉴 지원은 파일 가져오기 경로 중 하나이며 제품의 중심이 아니다.

외부 CSS/JS/이미지가 있는 문서는 묶음 가져오기, 경로 보존, 진입 HTML 선택, 누락 리소스 표시와 경로 이탈 방지가 필요하다. 서버 기능은 리더가 자동 제공하지 않는다.

## 빌드와 실기기 확인

Mac과 Xcode에서 iOS 프로젝트를 빌드하고 Simulator를 먼저 확인한다. 실제 아이폰에 설치하려면 앱 서명과 실행 기기 설정이 필요하다. 직접 Mac을 사용하기 어렵다면 준비된 서명 빌드를 TestFlight로 전달받는 방식이 가능하지만, 빌드와 배포 계정 준비는 여전히 필요하다.

현재 저장소에는 설치형 iOS 앱 프로젝트나 설치 빌드가 없다. 웹 리더 검증 결과를 iOS 실기기 설치 앱의 검증 결과로 해석하지 않는다.
