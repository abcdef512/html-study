# 모바일 HTML 리더 요구사항 명세서

버전 1.1 / 2026년 10월 12일 / 프로젝트 HTML Reader

## 제품 목표

PDF 리더가 기기의 PDF를 읽듯이, 아이폰에서 저장된 HTML을 가져와 화면을 읽고 파일 내부의 JavaScript 기능까지 사용한다. 문서, 계산기, 입력 폼, 학습 자료 등 여러 HTML을 지원한다. 모의고사는 실행 호환성을 검증하는 예제다. Mattermost 공유 연동은 핵심 목표가 아니다.

페르소나는 이동 중 휴대폰으로 자료를 확인하는 20대 대학생 웹 개발자다. 파일을 열기 위해 매번 PC를 켜거나 문서마다 웹에 업로드하지 않고, 리더에서 가져와 읽고 필요한 경우 소스를 수정한다.

## 범위와 단계

- 현재 웹 리더 P0: 기기의 단일 HTML 선택, CSS/JavaScript 실행, 보관 목록과 재열람, 파일별 저장 격리, 검색, 넓게 읽기, 원본과 수정본 내보내기.
- 보조 편집 기능: 소스 확인, 초안 저장, 적용과 재실행, 실행 취소, 원본 복구.
- 다음 P1: 상대 경로 CSS/JS/이미지를 포함한 파일 묶음 또는 ZIP 가져오기.
- 설치형 iOS 목표: 파일 선택기, 앱 내부 보관, WKWebView 실행, 파일 앱에서 열기 연결. 웹 리더와 별도 완료 기준으로 검증한다.
- 서버 실행, 정답 생성, AI 채점, 계정과 클라우드 동기화는 현재 범위에서 제외한다.

## 사용자 흐름

HTML 열기 → 파일 앱에서 선택 → 읽기 및 기능 사용 → 보관 목록에서 재열람.

소스 수정이 필요하면 소스 편집 → 초안 저장 → 적용하고 실행 → 원본 또는 수정본 내보내기를 사용한다. 편집 중 문서를 자동으로 재실행하지 않는다.

| FR09 | 모바일 기호 입력 보조, 실행 취소와 다시 실행을 지원한다. | 소스 수정과 취소가 동작하며 한글 조합 입력을 실기기에서 확인한다. |

| FR11 | 적용하고 실행으로만 실행본을 갱신한다. | 초안 편집 중 기존 화면이 유지되고 적용 후 변경이 반영된다. |
| FR12 | 재실행과 문서 저장 데이터 초기화를 구분한다. | 기본 재실행은 저장값을 보존한다. 명시적 초기화는 해당 파일 값만 지운다. |
| FR13 | 원본 소스, 초안과 마지막 실행본을 분리한다. | 소스 복구만으로 파일 저장 데이터를 지우지 않는다. |
| FR14 | 오류 로그와 실행 종료/복구를 제공한다. | 오류 후 소스 편집이 가능하다. 웹의 무한 반복 강제 종료는 미해결로 명시한다. |
| FR15 | 원본과 수정본 HTML을 구분해 UTF-8로 내보낸다. | 원본 텍스트와 초안이 구분된다. 파일 저장 데이터는 소스에 자동 주입하지 않는다. |
| FR16 | 원본 내용을 넓게 읽는 화면을 제공한다. | 아이폰 크기에서 읽기 화면을 종료하고 파일 관리와 편집으로 돌아갈 수 있다. |

## 저장 정책

- 가져온 HTML 소스와 편집 초안은 리더에 보관한다. 파일 선택만으로 서버에 업로드하지 않는다.
- 각 문서는 이름과 별개인 ID를 가진다. 이름 변경 시 ID와 저장 데이터를 유지한다. 새 사본은 소스만 복사하며 저장 데이터는 비운다.
- 원본이 localStorage에 기록하는 값만 지속 복원한다. 저장 기능이 없는 HTML의 폼 입력과 DOM 상태를 앱이 추정해 복원하지 않는다.
- sessionStorage는 같은 실행 세션과 독립된 새 세션을 구분한다. 모든 임의 타이머의 복원은 보장하지 않는다.
- 기존 모의고사의 타이머와 채점은 파일 내부 코드로 실행한다. 앱은 모의고사의 문항, 정답과 답안을 해석하지 않는다.
- 저장 완료 표시는 IndexedDB 트랜잭션 완료 후 표시한다. 강제 종료 직전 아직 저장되지 않은 입력은 보장하지 않는다.
- 업데이트는 기존 `html-study-v1` 데이터베이스를 유지한다. 다른 배포 주소, 데이터 삭제 또는 저장 공간 회수에서는 보존을 보장하지 않는다.

## 지원 범위

첫 단계는 자체 완결 단일 HTML이다. 별도 CSS, JS, 이미지 파일, 서버 API, CDN과 모듈 import가 필요한 문서는 전체 동작을 보장하지 않는다. 리더는 백엔드나 Node.js 서버를 대신 실행하지 않는다.

원본의 디자인을 기본 유지하며 모바일 대응이 없는 HTML에는 원본의 넘침이 있을 수 있다. 앱의 어두운 화면 설정으로 원본 CSS까지 바꾸지 않는다. 소스 수정과 문서 저장 데이터 초기화는 서로 별개다.

## 개발 진행 순서

1. 일반 HTML 리더 흐름과 실제 파일별 실행 및 저장을 검증한다.
2. 파일 묶음의 진입 HTML, 상대 경로 자원과 저장 격리 정책을 구현한다.
3. iOS 파일 선택기와 WKWebView 저장 및 실행 수명 주기를 실기기에서 검증한다.
4. 파일 앱에서 열기 연결을 추가한다. 특정 메신저 연동은 부가 경로로 취급한다.
